# Bibliarium

Личная библиотека книг для Android. Всё локально: ни сервера, ни аккаунтов, ни сети.

## Сборка

Локально проект не собирается — только GitHub Actions.

Пуш в `main` запускает workflow `.github/workflows/build.yml`. Готовый debug APK лежит
в артефактах запуска: вкладка **Actions** → последний запуск → **Artifacts** →
`bibliarium-debug-apk`.

Всё, от чего зависит воспроизводимость, прибито гвоздями:

- JDK задан числом (`17`), не latest и не автоопределение
- `compileSdk` держится на стабильной платформе 36, а не на preview
- версия Gradle задаётся только wrapper'ом; `gradle/wrapper/gradle-wrapper.properties`
  закоммичен, `distributionUrl` указывает точную версию, `distributionSha256Sum`
  проверяет скачанный дистрибутив
- `gradle-wrapper.jar` сверен с контрольной суммой, опубликованной Gradle
  (`76805e32…93f3` для 9.1.0)
- все версии зависимостей — числа в `gradle/libs.versions.toml`, ни одного `+`
  и ни одного `latest.release`
- кеш Gradle включён в workflow: в `main` пишется, в PR только читается

## Стек

Версии сверены с Maven Central и Google Maven 19.09.2026. Взят согласованный набор,
на котором собирается Readium 3.3.0 — вся связка держится на стабильном compileSdk 36.

| | версия |
|---|---|
| Gradle | 9.1.0 |
| Android Gradle Plugin | 9.0.0 (Kotlin встроен в AGP 9, отдельный KGP не подключается) |
| Kotlin | 2.3.20 |
| JDK | 17 |
| compileSdk / targetSdk | 36 |
| minSdk | 26 |
| Compose | 1.10.5, Material3 1.4.0 |
| Room | 2.8.4 (KSP 2.3.4) |
| Readium Kotlin Toolkit | 3.3.0 |
| Coil | 3.5.0 |

### Почему не самые свежие версии

Readium 3.4.0, androidx core 1.19.0, Compose 1.12.x и Coil 3.6.x объявляют в метаданных
AAR `minCompileSdk=37`. Платформы `android-37` в стабильном канале SDK нет — в
репозитории Google максимум `platforms;android-36`, а 37 существует только как
`platforms;android-CANARY`. Собирать приложение, которое ставится на телефон, против
preview-платформы — ровно тот случай, когда сборка ломается задним числом, поэтому
взята предыдущая согласованная волна версий. Все `minCompileSdk` проверены по
метаданным AAR, а не на глаз.

## Архитектура

Хранение вынесено за интерфейс, потому что позже переедет на сервер:

```
BookStore      ← LocalBookStore (файлы в filesDir/books, метаданные в Room)
HighlightStore ← LocalHighlightStore
```

UI и остальные слои о реализациях не знают и работают с доменными типами
(`domain/Book.kt`, `domain/Highlight.kt`, `domain/Shelf.kt`). Когда появится сервер,
добавляется `RemoteBookStore` — остальной код не трогается.

DI-фреймворка нет: всё собирается в `AppContainer`, который создаётся в `BibliariumApp`.

Токены оформления живут в `ui/theme/Tokens.kt`. В экранах не должно быть ни одного
литерала цвета или размера — только `BibliariumTheme.colors` / `.type` / `.spacing` / `.shapes`.

## Форматы

EPUB читает Readium — своего парсера нет и не будет.

FB2 Readium не поддерживает (проверено по списку форматов toolkit 3.4.0), поэтому название,
автор, жанр и обложка берутся напрямую из блока `<description>` FB2-файла
(`data/importer/Fb2MetadataReader.kt`). Это только метаданные, не движок рендеринга.

Чтобы движок чтения остался один, FB2 будет конвертироваться в EPUB при импорте —
это отдельный подэтап со своим прогоном сборки, см. список этапов. `Book.format`
при этом остаётся `FB2`: пользователю показывается тот формат, который он добавил.

`.fb2.zip` поддерживается: архив распаковывается потоком сразу в целевой файл,
без временного файла на диске и без чтения книги целиком в память.

PDF и DJVU не импортируются, но `Book.format` их уже знает: экран чтения будет выбирать
движок по формату.

## Поиск книг на телефоне

Человек обычно не помнит, в каких папках лежат его книги, поэтому «Добавить книгу»
ведёт на развилку: поиск по телефону или обычный системный выбор файла.

Как устроен поиск:

- корневая папка выбирается один раз через `ACTION_OPEN_DOCUMENT_TREE`, разрешение
  берётся persistable и сохраняется в DataStore. `MANAGE_EXTERNAL_STORAGE` не
  запрашивается ни в каком виде
- обход идёт запросами к `DocumentsContract`, а не через `DocumentFile.listFiles()`:
  DocumentFile на каждое имя, размер и тип делает отдельный запрос к провайдеру, и на
  папке с тысячами файлов это занимает минуты. Здесь на каждую папку приходится один
  курсор со всеми колонками сразу — тот же SAF, просто запрошенный пачкой
- ищутся `.epub`, `.fb2`, `.fb2.zip`, `.pdf` и голый `.zip`, внутри которого есть fb2
  (проверка ограничена размером архива и числом записей)
- `Android/data` и `Android/obb` пропускаются — они и так закрыты для SAF.
  `Android/media` не пропускается: именно там лежат файлы из Telegram
- обход отменяется кнопкой; каждые 25 найденных файлов отправляется промежуточный
  снимок, поэтому отмена не теряет уже найденное
- названия читаются отдельным проходом уже после того, как список показан: открывать
  каждую книгу движком во время обхода — значит заставить ждать вместо того, чтобы
  сразу показать найденное

Уже добавленные книги определяются по размеру файла и SHA-256 первых 64 КБ, а не по
имени: одна книга часто лежит в двух местах под разными именами. Хэш считается только
для файлов, чей размер вообще встречается в библиотеке. Отпечаток снимается с исходного
файла, а не с того, что легло в `filesDir`, — иначе повторный поиск не узнал бы книгу,
добавленную из `.fb2.zip`.

По умолчанию показываются только новые файлы; переключатель «Только новые» открывает
и уже добавленные — они помечены серым и выключены.

Пакетный импорт идёт через WorkManager, очередь лежит в таблице `import_queue`.
Поэтому импорт не прекращается при сворачивании приложения и переживает смерть
процесса: воркер продолжит с первой невыполненной записи. Битый файл не роняет пачку —
причина отказа пишется в очередь, в конце показывается «Добавлено N, пропущено M»
с раскрытием списка проблемных файлов.

## Этапы

1. Каркас, Room, `BookStore`, импорт EPUB, простой список
1.5. **Поиск книг на телефоне и пакетный импорт** ← сейчас здесь
2. Полка с генерацией корешков, ярусы, режим сетки
2.5. **Конвертер FB2 → EPUB** — отдельный подэтап: картинки из base64, сноски
   из `<body name="notes">`, проверка на реальной книге с картинками и сносками
3. Чтение через Readium, сохранение позиции, настройки
4. Выделения и список цитат
5. Поиск, фильтры, ручные полки
6. Вторая тема, тёмный режим, полировка по `DESIGN.md`

Каждый этап заканчивается установленным на телефон APK.

## Шрифты

`res/font/` — Literata, IBM Plex Sans, Manrope, Inter. Все вариативные, лежат файлами:
приложение офлайн, по сети ничего не тянется. Лицензии — в `licenses/`.

## Дизайн

`design/literary_archive/DESIGN.md` — источник истины по внешнему виду.
`design/bibliarium_1` и `design/bibliarium_2` — референсы экранов полки и чтения;
HTML оттуда используется как справка по значениям, а не как разметка.
